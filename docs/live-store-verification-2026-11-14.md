## Failure trace and next steps

1. **Restore the app's recognition of this installed shop.** The `Invalid shop` body matches the guard in [`api.session.tsx`](../app/routes/api.session.tsx), immediately after proxy verification and before a session is issued. [`isInstalledShop`](../app/models/installedShop.server.ts) checks cached installation state, then the active datastore's session/shop records. This source trace points to installation recognition in the deployed app; this run did not inspect the production database and does not prove which record, environment or installation lifecycle caused it. Open AOVBoost through Shopify Admin and complete its normal authentication if prompted; then verify a genuine storefront session returns signed JSON. If it remains invalid, inspect the intended production datastore and app installation/proxy association. Do not bypass signature or installation checks, insert a fabricated token or weaken the guard to make QA pass.
2. **Repair the configured Redis service/connection separately.** The DNS failure is confirmed in production logs. It is a separate defect; the evidence does not establish that it causes the `Invalid shop` response. A successful HTTP app page or matching SDK cannot certify Redis, billing or shared usage.
3. **Resume the flow at signed bootstrap.** Once it succeeds, test native shopper add → one offer → one attributed acceptance → immediate cart refresh → no recursive offer, on desktop and a narrow viewport. Then verify chat and any merchant-enabled widgets, tracking and authenticated Admin pages. Preserve and specifically recheck the cart-refresh correction.
4. **Test the new core under an explicitly configured QA rollout.** It is currently off. Matching published chunks do not verify Arbiter behavior. Verified factual inputs and reserved app-owned placements are also needed before testing the factual widgets; do not invent data or change merchant settings merely to obtain a screenshot.

No application/backend code, Redis configuration, billing setting, merchant setting, theme file, checkout extension or production deployment was changed. No browser profile, existing cookies or authentication state was imported or exported. The supplied store password, session credentials, raw chat content and raw theme settings were not saved in evidence. The isolated browser tabs remain available for normal Admin sign-in so verification can continue.
